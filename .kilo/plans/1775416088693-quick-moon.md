## Implementation Steps

### Step 1: Define `.light` tokens in `tokens.css`

Add a `.light {}` block after the existing `.dark {}` block. Choose warm or neutral variant (or blend). The `:root` stays dark as default.

**File:** `styles/tokens.css`

- Add `.light { ... }` with the chosen palette
- Add `.light` overrides for `card-surface` shadow (lighter shadow)
- Add new tokens: `--accent-warm`, `--accent-cool` (new, for marble pattern accents)
- Add `--surface-light`, `--surface-light-text`, `--surface-light-border` tokens (referenced in `globals.css` but never defined)

### Step 2: Update `globals.css` for theme-aware styles

**File:** `styles/globals.css`

- `a:hover` (line 34): `color-mix(in oklab, var(--text), white 12%)` → replace with `color-mix(in oklab, var(--text), black 8%)` or use a CSS variable
- `.chip:hover` (line 55): same fix
- `.table tbody tr:hover` (line 88): same fix
- `.card-surface` (line 61–66): Add `.light .card-surface` with lighter box-shadow
- `.card-surface:hover` (line 116): Fix `white 16%` → theme-aware
- `.btn-outline:hover` (line 204): Fix `white 20%` → theme-aware

Strategy: use `.dark` / `.light` prefixed rules, or use `color-scheme` to flip the mixing direction.

### Step 3: Update `tailwind.config.js` — Tremor chart colors

**File:** `tailwind.config.js`

Add a light-mode Tremor palette. Two approaches:

**Option A (recommended):** Make Tremor colors reference CSS variables:

```js
tremor: {
  brand: {
    faint: "var(--tremor-brand-faint)",
    muted: "var(--tremor-brand-muted)",
    // ...
  },
  background: {
    DEFAULT: "var(--tremor-bg)",
    // ...
  },
}
```

Then define `--tremor-*` variables in `tokens.css` with dark/light values.

**Option B:** Hardcode light Tremor colors in a separate config and swap at runtime.

Option A is cleaner — keeps everything in one place.

### Step 4: Wire ThemeSwitch into navbar

**File:** `components/navbar.tsx`

- Import `ThemeSwitch` from `@/components/theme-switch`
- Add `<NavbarContent justify="end">` with `<ThemeSwitch />`
- Minimal, just the icon toggle on the right side of the navbar

### Step 6: Fix hardcoded component colors — Category 2 (Should Adapt)

27 instances of semi-transparent tints. These generally work okay in light mode but may need subtle tweaks:

- `bg-orange-500/10` → `bg-orange-500/15` (slightly more visible on light surfaces) — affects `hash-account-title.tsx`, `guild/constants.ts`, `item-contracts.tsx`, `item-contracts-chart.tsx`
- `hover:text-orange-400` → `hover:text-orange-500` (slightly darker for contrast on white) — affects `guild-roster.tsx`, `character-stats.tsx`
- Error boundary tints stay as-is (they're already subtle enough)
- `text-orange-300` in heatmap tooltip → `text-orange-600` (same reasoning as step 5)

> **Note:** Many `/10` and `/20` opacity tints look fine on both themes. Only adjust if visual testing reveals contrast issues. This step can be deferred to a visual QA pass.

### Step 7: Update `components/primitives.ts`

**File:** `components/primitives.ts`

- The `title` variant has `foreground: "dark:from-[#ffffff] dark:to-[#b3b3b3]"` which already uses `dark:` prefix
- Add light-mode gradient: `from-[var(--gradient-start)] to-[var(--gradient-end)]` as the base, or add explicit light foreground colors
- The `indigoCyan` color already uses CSS variables, so it inherits the marble gradient automatically

### Step 8: Visual QA & iteration

After implementing steps 1–7:

3. Visit each route: `/`, `/character/*`, `/guild/*`, `/item/*`, `/hash/*`
4. Check for contrast issues in:
